3.3 工作原理总结

  1. utm_moc52 启动 → 向 Redis 写入 2000 架无人机的完整飞行计划和空域数据
  2. 每秒循环 → 仿真所有无人机沿航线飞行，向 Kafka 发送实时位置、速度、高度等遥测
  3. ATC Dashboard 后端 → 从 同一个 Redis 读取飞行计划和空域，从 同一个 Kafka 消费遥测数据
  4. ATC Dashboard 前端 → 在 dkkgsit-test.testdolphin.com/atc/dashboard 页面上实时渲染：

    - 地图上 2000 个无人机图标沿航线移动
    - 航线轨迹线展示
    - 空域/禁飞区多边形
    - 冲突检测告警
    - 无人机详情面板（速度、高度、航向等）

核心原理：utm_moc52 扮演"虚拟无人机群"的角色，通过共享的 Redis/Kafka 基础设施向 ATC 系统注入仿真数据，使 Dashboard 看起来就像在监控真实的无人机交通。无需修改 Dashboard 代码——它对数据来源（真实 vs 仿真）完全无感知。
