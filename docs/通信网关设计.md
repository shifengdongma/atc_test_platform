## 通信网关设计

### 1 服务功能

`al-atc-datasync-agent` 是低空空管系统侧的 **TCP 网关服务**，承担以下职责：

- 作为 TCP 服务端（端口 9000），接受代理程序的持久化长连接
- 接收代理上报的监视数据（UAV_SURVEILLANCE）、心跳（HEARTBEAT）、指令回复（COMMAND_RESPONSE），路由到对应处理逻辑
- 从 Kafka `agent_command` 消费控制指令，通过 TCP 转发给对应代理；代理离线时暂存指令，重连后补发
- 将监视数据转换为 `UavRuntimeDataDTO` 写入 Kafka `uav_runtime_data`
- 将指令回复转发到 Kafka `agent_command_response`
- 代理断连时清除会话并向 Kafka `uav_agent_offline` 发送离线通知

### 2 通信方式

与代理程序间通过TCP通信，与业务服务间通过Kafka通信。

### 3 数据流

#### 3.1 上行：监视数据（代理 → 网关 → Kafka）

```
代理  ──[UAV_SURVEILLANCE, TCP]──►  AgentChannelHandler
                                       │ 1. msg_id 幂等去重（TTL 5s，上限 50000）
                                       │ 2. 路由到 AgentMessageService
                                       ▼
                                   handleSurveillance()
                                       │ 1. AgentSurveillanceConverter → UavRuntimeDataDTO
                                       │    (sourceType=1, receiveTime=本地时钟,
                                       │     reportTime=无人机侧 timestamp)
                                       │ 2. AgentKafkaProducer.sendSurveillanceData()
                                       ▼
                               Kafka: uav_runtime_data
                               (Key=uav_id, Value=UavRuntimeDataDTO JSON)
```

#### 3.2 上行：心跳（代理 → 网关）

```
代理  ──[HEARTBEAT, 每10秒, TCP]──►  AgentChannelHandler
                                        │ IdleStateHandler 重置超时计时器
                                        ▼
                                    handleHeartbeat()
                                        │ 记录 agent_id / status / connected_uavs
                                        │ （心跳仅用于保活检测，不写 Kafka）
                                        ▼
                                    [日志记录]

超时检测：30秒内无任何消息 → IdleStateEvent → ctx.close()  超时 通信网关不关
         → channelInactive → 清除会话 → Kafka: uav_agent_offline
```

#### 3.3 上行：指令回复（代理 → 网关 → Kafka）

```
代理  ──[COMMAND_RESPONSE, TCP]──►  AgentChannelHandler
                                       │ 路由到 handleCommandResponse()
                                       │ 记录 uav_id / command_id / status
                                       ▼
                               AgentKafkaProducer.sendCommandResponse()
                                       ▼
                               Kafka: agent_command_response
                               (Key=uav_id, Value=COMMAND_RESPONSE data JSON)
                               消费方：la-atc-biz-backend服务负责消费处理
```

#### 3.4 下行：控制指令（Kafka → 网关 → 代理）

```
Kafka: agent_command
(la-atc-biz-backend 通过 algorithmStringKafkaTemplate 生产)
       │
       ▼
AgentKafkaConsumer.onAgentCommand()
       │ 1. 解析 JSON，取 data.uav_id
       │ 2. sessionManager.getChannelByUavId(uav_id)
       ├─► 找到活跃连接 → channel.writeAndFlush(message + "\n")
       │                  → 失败记录 warn 日志
       └─► 未找到连接    → enqueuePendingCommand(uavId, ...)
                          → 代理重连时 flushPendingCommands() 补发
                          → 超过 commandPendingMaxSeconds(300s 可以配置时间) 丢弃
```

#### 3.5 断连处理

```
代理 TCP 断开（网络故障 / 心跳超时 / 主动断开）
       │
       ▼
AgentChannelHandler.channelInactive()
       │ 1. sessionManager.unregister(ip)
       │    → 从 ipChannelMap 移除
       │    → 从静态 uavIdIpMap 反查该 IP 下所有 uav_id
       │ 2. kafkaProducer.sendOfflineEvent(ip, uavIds)
       ▼
Kafka: uav_agent_offline
(Key=agentIp, Value={ "agentIp":"...", "uavIds":[...], "disconnectTime":... })
消费方：la-atc-biz-backend服务负责消费处理
```

### 4 消息协议（v3.1）

通用消息头：

```json
{
  "version": "1.0",
  "msg_id": "uuid-string",
  "timestamp": 1234567890000,
  "msg_type": "xxx",
  "sender": "system | agent",
  "data": { }
}
```

#### 4.1上行消息（代理 → 网关）

##### UAV_SURVEILLANCE（1~5 Hz 周期上报）

```json
{
  "msg_type": "UAV_SURVEILLANCE", "sender": "agent",
  "data": {
    "uav_id": "UAV-001",
    "classification": 1,
    "mav_type": 2,
    "timestamp": 1234567890123,
    "position": { "lat": 31.123456, "lon": 121.123456, "alt": 120.5, "alt_relative": 50.0 },
    "velocity": { "vn": 5.2, "ve": 3.1, "vd": -0.5 },
    "attitude": { "roll": 0.5, "pitch": -0.3, "yaw": 45.0 },
    "track_angle": 45.0,
    "vertical_speed": -0.5,
    "status": { "mode": "AUTO", "battery": 85.5, "armed": true, "connected": true, "ground_speed": 10.2 },
    "mission": {
      "current_waypoint": 3, "total_waypoints": 10,
      "plan": [{ "seq": 0, "lat": 31.1, "lon": 121.1, "alt": 50.0 }]
    }
  }
}
```

> `mav_type`：MAVLink MAV_TYPE 枚举值（0=通用，1=固定翼，2=四旋翼，13=六旋翼等）

##### HEARTBEAT（每 10 秒）

```json
{
  "msg_type": "HEARTBEAT", "sender": "agent",
  "data": {
    "agent_id": "agent-001",
    "status": "running",
    "connected_uavs": ["UAV-001", "UAV-002"],
    "timestamp": 1234567890000
  }
}
```

> `status` 枚举：`running` / `busy` / `error`

##### COMMAND_RESPONSE（收到指令后立即回复，后续周期更新进度）

```json
{
  "msg_type": "COMMAND_RESPONSE", "sender": "agent",
  "data": {
    "uav_id": "UAV-001",
    "command_id": "cmd-uuid",
    "command_code": "CMD_SET_FLY_PLAN",
    "status": "executing",
    "progress": 50,
    "result": {
      "success": true,
      "message": "执行中"
    },
    "timestamp": 1234567890123
  }
}
```

> `status` 枚举：`accepted` / `rejected` / `executing` / `completed` / `failed`

> `result.mission`：`command_code=CMD_QUERY_MISSION` 时携带，包含 `current_waypoint`、`total_waypoints`、`plan`

##### ERROR（协议层错误，无法关联到具体指令时使用）

```json
{
  "msg_type": "ERROR", "sender": "agent",
  "data": {
    "error_code": 4000,
    "error_msg": "JSON 解析失败",
    "original_msg_id": "uuid"
  }
}
```

> 能携带 `command_id` 的错误使用 `COMMAND_RESPONSE`（status=failed），无法关联才用 `ERROR`

#### 4.2下行消息（网关 → 代理，通过 Kafka `agent_command` 投递）

所有下行消息字段：`uav_id`、`command_code`、`command_id`（必填）

##### SET_FLY_PLAN 飞行计划下发

```json
{
  "msg_type": "SET_FLY_PLAN", "sender": "system",
  "data": {
    "uav_id": "UAV-001", "command_code": "CMD_SET_FLY_PLAN", "command_id": "uuid",
    "params": {
      "mission": [
        { "seq": 0, "lat": 31.1, "lon": 121.1, "alt": 50.0 },
        { "seq": 1, "lat": 31.2, "lon": 121.2, "alt": 60.0 }
      ],
      "takeoff_time": "1783056194936"
    }
  }
}
```

##### QUERY_MISSION 任务查询

```json
{
  "msg_type": "QUERY_MISSION", "sender": "system",
  "data": { "uav_id": "UAV-001", "command_code": "CMD_QUERY_MISSION", "command_id": "uuid" }
}
```

##### RISK_UAV_CROSSING（冲突解脱 — 避让点）

```json
{
  "msg_type": "RISK_UAV_CROSSING", "sender": "system",
  "data": {
    "uav_id": "UAV-001", "command_code": "CMD_SET_TARGET_POSITION", "command_id": "uuid",
    "params": { "target_position": { "lat": 31.1, "lon": 121.1, "alt": 50.0 }, "speed": 10.0 },
    "reason": "短期冲突：UAV-002距离过近，预计15秒后冲突"
  }
}
```

##### RISK_UAV_REAR_END（间隔保持 — 追尾碰撞）

```json
{
  "msg_type": "RISK_UAV_REAR_END", "sender": "system",
  "data": {
    "uav_id": "UAV-001", "command_code": "CMD_SET_SPEED", "command_id": "uuid",
    "params": { "speed": 8.0, "adjust_type": "decelerate", "duration": 30 },
    "reason": "预计180秒后与UAV-003间隔小于标准值"
  }
}
```

##### RISK_RESTRICTED_ZONE（紧急避让 — 禁飞区换航）

```json
{
  "msg_type": "RISK_RESTRICTED_ZONE", "sender": "system",
  "data": {
    "uav_id": "UAV-001", "command_code": "CMD_SET_NEW_MISSION", "command_id": "uuid",
    "params": { "mission": [{ "seq": 0, "lat": 31.1, "lon": 121.1, "alt": 50.0 }] },
    "reason": "禁飞区临时开启，原航线进入禁飞区范围"
  }
}
```

##### RETURN_TO_LAUNCH（返航）

```json
{
  "msg_type": "RETURN_TO_LAUNCH", "sender": "system",
  "data": { "uav_id": "UAV-001", "command_code": "CMD_RETURN_TO_LAUNCH", "command_id": "uuid", "reason": "电量低于15%" }
}
```
