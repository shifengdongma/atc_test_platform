## 轨迹预测

<u>预测每个无人机下1秒的位置</u>，如通无人机没有上报位置，使用历史数据继续推测30秒（参数化），然后终止。

结果存入 redis 。 key为 uav*runtime_trace*时间戳 类型为 <u>set，set中存放每一个无人机的下一秒的预测位置。</u>

注意 需要添加ttl 时间为 <u>10</u>s（参数化）

**兼容ADS-B数据，通过sourceType字段与无人机数据区分。**

| key           | value |
| ------------- | ----- |
| 实际数据的key | { }   |

其中value

| 字段                            | 名称                                               | 类型    |
| ------------------------------- | -------------------------------------------------- | ------- |
| uniqueProductIdentificationCode | 唯一产品识别码                                     | String  |
| longitude                       | 经度                                               | Double  |
| latitude                        | 纬度                                               | Double  |
| trackAngle                      | 航迹角 0 - 359.9                                   | Double  |
| speed                           | 地速                                               | Double  |
| altitude                        | 高度                                               | Double  |
| verticalSpeed                   | 垂直速度 正代表上升 负值代表下降                   | Double  |
| timestamp                       | 时间戳                                             | Long    |
| isReportPosition                | 无人机上报后最近一秒预测位置(true)/预测点位(false) | Boolean |
| operatingStatus                 | 015 运行状态                                       | Integer |
| disappear                       | 消失状态，1-无人机消失 2-外推轨迹                  | Integer |
| sourceType                      | 数据来源                                           | Integer |
| addInf                          | 附加字段                                           | Object  |
| + cs                            | 航班号                                             | String  |
| + gbs                           | 是否在地面                                         | Integer |
| + bvr                           | 几何垂直速率                                       | Integer |
| + nacp                          | 位置导航精度类别                                   | Integer |
| + sil                           | 监视完好性水平                                     | Integer |
| + tsps                          | 飞机状态中的PS项                                   | Integer |
| + ssr                           | SSR代码                                            | String  |
|                                 |                                                    |         |
|                                 |                                                    |         |

每次生成预测，将redis key 通过kafka 发送

topic: uav_runtime_trace

| 字段      | 名称            |     |
| --------- | --------------- | --- |
| redisKey  | redis 存放的key |     |
| timestamp | 生成预测的时间  |     |
|           |                 |     |

## 航线冲突检测

飞行任务/飞行计划提交与审批阶段，系统基于所有已提交和已批准的飞行计划，在四维（空间+时间）空域内进行冲突仿真与检测的过程。其目的是在航空器起飞前，识别并解决计划航路在时空上的潜在交叠，实现空域资源的预先安全分配。

对应业务场景中：

    1. 单次飞行任务+非隔离空域类型+需要自动审批
    1. 多次飞行任务计划+非隔离空域类型+需要自动审批

协议 http

请求类型 POST

请求content-type: application/json

### 待检测航线相关数据库表结构

查询飞行计划表，可关联飞行任务表、飞行任务时段表、飞行任务航线表、飞行任务航线段表。待检测数据需同时满足条件：

1、飞行计划状态为审批通过后直至执行结束前的所有状态，包括：审批通过、预激活、管制状态、非管制状态、悬挂。

2、飞行任务的空域类型为非隔离空域

3、上述所有表中未删除状态的数据，即 IS_DELETED =0

```java
-- 参考查询sql语句
SELECT * FROM flight_plan fp
LEFT JOIN flight_task ft ON fp.task_id = ft.id
LEFT JOIN flight_task_period ftp ON ftp.task_id = ft.id
LEFT JOIN flight_task_line ftl ON ftl.task_id = ft.id
LEFT JOIN flight_task_line_segment ftls ON ftl.id = ftls.task_line_id
LEFT JOIN flight_plan_uav_info fpui ON fpui.plan_id = fp.id
WHERE fp.is_deleted = 0
AND ft.is_deleted = 0
AND ftp.is_deleted = 0
AND ftl.is_deleted = 0
AND ftls.is_deleted = 0
AND fpui.is_deleted = 0
AND fp.flight_plan_status IN('APPROVED','PREA','CONTROL','UNCONTROL','SUSP')
AND ft.airspace_type = 'NON_SEGREGATED';
```

## 合作、非合作查询

无人机是合作或非合作，可查询redis。

1. redis key 为 uavCooperative
2. 使用 hash 存储，hash key 为每个无人机的**唯一识别码**，value为true或false

没查到或者value为false都表示非合作，value为true表示合作。

发生变更时通过http接口 /api/v1/utm/uavcooperative 同步给算法。
