## 三、MySQL 故障排查（按顺序执行）

### Step 0 — pymysql 版本检查（必须为 1.x）

```bash
docker exec utm-simulator python3 -c "import pymysql; print(pymysql.__version__)"
```

| 版本 | 状态 | 操作 |
|------|------|------|
| `1.x` | ✅ 正常 | 继续下一步 |
| `2.x` | ❌ 不兼容 | 热修复：`docker exec utm-simulator pip install 'pymysql==1.1.0'`，然后**重建镜像** |

> `1.4.6` 是 1.x 版本号，正常。pymysql 2.x 需降级。

### Step 2 — 模块导入测试

```bash
docker exec utm-simulator python3 -c "import sys; sys.path.insert(0,'/app/atc_api_autotest/api_tools'); from mysqldbclient import MysqlDbClient; print('OK')"
```

### Step 3 — 检查容器读取的 MySQL 配置

```bash
docker exec utm-simulator python3 -c "import sys; sys.path.insert(0,'/app/common'); from config import load_mysql_config; c=load_mysql_config(); print('host=%s port=%s user=%s db=%s configured=%s'%(c.host,c.port,c.user,c.database,c.configured))"
```

关键：`host` 不能是 `127.0.0.1`，`configured=True`

### Step 4 — TCP 连通性

```bash
docker exec utm-simulator timeout 5 bash -c "echo >/dev/tcp/10.165.32.147/3306 && echo TCP可达 || echo TCP不可达"
```

### Step 5 — pymysql 直连（不传 ssl，替换 `<实际密码>`）

```bash
docker exec utm-simulator python3 -c "import pymysql; c=pymysql.connect(host='10.165.32.147',port=3306,user='utm',password='<实际密码>',database='utm_simulator',connect_timeout=5); print('MySQL OK'); c.close()"
```

### Step 5b — pymysql 直连（传 ssl={}，用于隔离 SSL 问题）

```bash
docker exec utm-simulator python3 -c "import pymysql; c=pymysql.connect(host='10.165.32.147',port=3306,user='utm',password='<实际密码>',database='utm_simulator',ssl={},connect_timeout=5); print('MySQL OK'); c.close()"
```

> **诊断**：Step 5 正常但 Step 5b 报 Access denied → SSL 握手有问题（缺 `cryptography` 包或 TLS 版本不兼容）。
> 修复：`docker exec utm-simulator pip install cryptography`

### Step 5c — Docker 内网直连（MySQL 和容器在同一台机器）

```bash
docker exec utm-simulator python3 -c "import pymysql; c=pymysql.connect(host='1Panel-mysql-Jdmq',port=3306,user='utm',password='<实际密码>',database='utm_simulator',ssl={},connect_timeout=5); print('MySQL OK'); c.close()"
```

> `1Panel-mysql-Jdmq` 是 Docker 内网容器名，仅在 MySQL 与 utm-simulator 同机部署时可用。

### Step 6 — 查看容器 IP

```bash
docker exec utm-simulator hostname -I
```

### Step 7 — MysqlDbClient 直连（绕过 mysql_db_manager，用相同参数测试）

```bash
docker exec utm-simulator python3 -c "import sys; sys.path.insert(0,'/app/atc_api_autotest/api_tools'); from mysqldbclient import MysqlDbClient; c=MysqlDbClient(host='1Panel-mysql-Jdmq',port=3306,user='utm',password='<实际密码>',database='utm_simulator',charset='utf8mb4',read_timeout=120,write_timeout=120); c.connect(); print('Step7 OK')"
```

> Step 5 直连 pymysql 正常但 Step 7 失败 → `MysqlDbClient.connect()` 传的额外参数（`read_timeout=120,write_timeout=120,cursorclass=DictCursor`）导致问题。
> Step 7 正常但 Step 8 失败 → `_get_client()` 的 RLock/ping+SELECT1 逻辑有问题。

### Step 7b — 打印 load_mysql_config 返回的密码（十六进制，确认与硬编码一致）

```bash
docker exec utm-simulator python3 -c "
import sys; sys.path.insert(0,'/app/common')
from config import load_mysql_config
c = load_mysql_config()
print('password hex:', c.password.encode().hex() if c.password else '(empty)')
print('password len:', len(c.password) if c.password else 0)
"
```

> 与硬编码密码的 hex 对比，不一致则检查以下两个来源：

```bash
# 检查 env.py 中 MYSQL_PASSWORD 的实际值（含引号问题）
docker exec utm-simulator grep MYSQL_PASSWORD /app/utm_simulator/env.py

# 检查环境变量 UTM_MYSQL_PASSWORD
docker exec utm-simulator sh -c 'echo "UTM_MYSQL_PASSWORD=$UTM_MYSQL_PASSWORD"'
```

> 如果 env.py 中密码值带双引号如 `"eEkJ3GfJ3Pt8iH5r"`，去掉外层引号
> 或 Python 引号嵌套如 `'"password"'`，改为 `'password'`

### Step 7c — 直接调用 `_create_mysql_client` 并手写 connect（跳过 ping+SELECT1）

```bash
docker exec utm-simulator python3 -c "import sys; sys.path.insert(0,'/app'); sys.path.insert(0,'/app/database'); from mysql_db_manager import _create_mysql_client; c=_create_mysql_client(); print('connect:', c.connect() if c else 'client is None')"
```

> Step 7b 失败 → `load_mysql_config()` 返回的配置与 Step 7 硬编码不一致  
> Step 7b 通过但 Step 8 失败 → `_get_client()` 的 ping+SELECT1+RLock 逻辑有问题

### Step 8 — 完整 CRUD 测试

```bash
docker exec utm-simulator python3 -c "import sys; sys.path.insert(0,'/app'); sys.path.insert(0,'/app/database'); import mysql_db_manager; mysql_db_manager.init_tables(); rows=mysql_db_manager.query_all('sim_json_files'); print('sim_json_files:',len(rows),'rows')"
```

## 四、常见 MySQL 错误与解决

### 错误 1：`Access denied for user 'utm'@'172.18.0.x'`

**Step A** — 检查 MySQL 用户的 host 授权：
```sql
SELECT user, host, plugin FROM mysql.user WHERE user='utm';
```

| host 列 | 含义 |
|---------|------|
| `%` | 已授权所有 IP ✅ |
| `localhost` / `127.0.0.1` | 仅本机 ❌ |

若没有 `%`：
```sql
CREATE USER IF NOT EXISTS 'utm'@'%' IDENTIFIED BY '<密码>';
GRANT ALL PRIVILEGES ON utm_simulator.* TO 'utm'@'%';
FLUSH PRIVILEGES;
```

**Step B** — host 已有 `%` 仍 Access denied，检查认证插件：

```sql
SELECT user, host, plugin FROM mysql.user WHERE user='utm';
```

| plugin | 状态 | 解决 |
|--------|------|------|
| `mysql_native_password` | ✅ pymysql 原生支持 | 密码不对 → `ALTER USER 'utm'@'%' IDENTIFIED BY '密码'` |
| `caching_sha2_password` | ⚠ 需要 SSL | 传 `ssl={}` 即可，`MysqlDbClient` 默认已启用 |

**Step C** — 如果 `mysql_native_password` 插件未加载（MySQL 8.0+ 部分版本）：
```sql
ALTER USER 'utm'@'%' IDENTIFIED WITH mysql_native_password BY '密码';
-- 报错: ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded
```

这说明 MySQL 服务器**不支持** `mysql_native_password`，只能走 `caching_sha2_password` + SSL。**不需要改插件**，只需确认容器连接时传了 `ssl={}`。

`MysqlDbClient` 默认 `use_ssl=True`，已自动传 `ssl={}`。如果仍失败，检查容器 OpenSSL 版本：
```bash
docker exec utm-simulator python3 -c "import ssl; print(ssl.OPENSSL_VERSION)"
```

**Step D** — 确认密码本身正确。在 MySQL 服务器本机验证：
```sql
SELECT user, host, plugin FROM mysql.user WHERE user='utm';
ALTER USER 'utm'@'%' IDENTIFIED BY 'eEkJ3GfJ3Pt8iH5r';
FLUSH PRIVILEGES;
```

### 错误 2：`Can't connect to MySQL server`

容器网络不通。
```bash
docker exec utm-simulator ping -c 3 10.165.32.147
docker network inspect atc_test_platfrom_utm-net
```

### 错误 3：`Protocol error, expecting EOF`

多线程并发导致 pymysql 数据包错乱（已通过查询加锁修复）。更新代码后重建镜像。

### 错误 4：`MySQL 未配置 (UTM_MYSQL_HOST 未设置)`

在 docker-compose.yml 或 1Panel 环境变量中添加：
```yaml
UTM_MYSQL_HOST=10.165.32.147
UTM_MYSQL_PORT=3306
UTM_MYSQL_USER=utm
UTM_MYSQL_PASSWORD=<密码>
UTM_MYSQL_DB=utm_simulator
```

### 错误 5：`SyntaxError: invalid syntax`（复制命令后）

原因：多行命令中的换行被终端替换成了空格。

解决：用 `;` 分隔多句 Python，或确认粘贴时保留了换行符。
