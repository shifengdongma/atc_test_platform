## 一、项目概述

### 1.1 项目定位

低空空管自动化测试平台，服务于"海豚"（Dolphin）ATC 态势感知 Dashboard（`dkkgsit-test.testdolphin.com`），实现三大核心能力：

1. **无人机仿真注入（`utm_simulator/`）** — 通过模拟器向 Redis/Kafka 注入仿真数据，驱动 Dashboard 展示
2. **API 自动化测试（`atc_api_autotest/`）** — 对 ATC 后端 REST API 进行功能验证、数据一致性校验
3. **高可用测试（`atc_ha_test/`）** — 双集群故障切换验证、数据同步一致性检查、大规模压力测试

### 1.2 核心技术原理

```
模拟器扮演"虚拟无人机群" → 共享 Redis/Kafka 基础设施 → 注入仿真数据
                                                          ↓
                                          ATC Dashboard 对数据来源（真实 vs 仿真）完全无感知
```

### 1.3 技术栈

| 组件 | 技术选型 |
|------|----------|
| 语言 | Python 3.11（Conda 环境 `utm`） |
| Web 框架 | Flask + Socket.IO（async_mode=threading） |
| 前端 | 原生 HTML/CSS/JS（Chart.js + Leaflet + Socket.IO CDN） |
| 缓存/存储 | Redis（飞行计划、空域数据） |
| 消息队列 | Kafka（遥测数据、轨迹预测反馈） |
| 本地数据库 | MySQL（主数据库：配置/文件/任务/日志，pymysql 1.x） |
| 远程数据库 | 达梦 DM（ATC 业务数据，只读） |
| C++ 核心库 | ctypes 封装（`pylib/`，与 `libutm_core` 二进制兼容） |
| 容器化 | Docker + docker-compose（Python 3.11-slim 镜像） |
| 实时协议 | WebSocket STOMP（SockJS，自实现握手） |
| AI 集成 | OpenAI 兼容 API（LLM 数据生成）+ Claude Code MCP 协议 |

## 七、仿真运行模式

### 7.1 三种模式对比

| 维度 | dynamic（动态仿真） | replay（预生成回放） | plan（Redis插值） |
|------|-------------------|-------------------|-------------------|
| **入口** | `main.py` / sim_manager | `tools/run_kafka.py` / `run_kafka_alive.py` | `tools/run_plan.py` |
| **数据来源** | `Simulator` 实时生成 | `mock/` 目录预生成JSON | Redis `BIZ_DATA:UAV_ROUTE` 现有计划 |
| **遥测生成** | 动力学仿真（加速/减速/爬升/降落） | 预记录数据点回放 | 航段几何线性插值 |
| **Redis** | 仿真过程动态写入 | 启动时一次性写入 + 单机循环刷新 | 仅读取 + 时间平移回写 |
| **禁飞区** | ✅ 动态生成 | ❌ | ❌ |
| **部署方式** | `deploy.sh` | `deploy_repeat.sh`（生产主力） | 直接运行 `tools/run_plan.py` |
| **适用场景** | 开发调试、算法验证 | 生产长期注入、精确回放 | 轻量注入、对接已申报计划 |

### 7.2 数据生成工具链

| 工具 | 功能 | 输出 |
|------|------|------|
| `tools/create_data.py` | 基于Simulator引擎批量生成 | `mock/redis_route.json` + `mock/kafka_data.json` |
| `tools/create_data_scene.py` | 单机场景（指定航线/偏离） | `mock/*_scene.json` |
| `tools/create_data_scenes.py` | 统一场景生成器 | parallel(平行飞行)/collision(碰撞预警)/status(状态告警)/scale(模板扩展)/batch(批量预设) |
| `web_data_gen_bridge.py` | Web前端调用桥接 | `mock/` 目录 |
| `ai_data_gen.py` | LLM API生成 | 数据库 `sim_json_files` 表 |

## 十、关键技术决策

### 10.1 WebSocket STOMP 自实现

`situation_monitor.py` 自行实现 SockJS+STOMP 握手协议（不依赖 `stomp.py`），与 ATC 后端协议完全匹配，支持指数退避断线重连（3s→30s）。

### 10.2 JWT Token 双重缓存

- `Jwt_Token_get.py`：模块级 `_token_cache` 字典，含 exp 解析，过期自动重新登录
- `SituationMonitor._get_token()`：实例级缓存，返回前检查 `exp > now + 60s`，过期则清除并调用 `get_jwt_token()` 重新获取

### 10.3 API优先 + Redis兜底

`_fetch_plan_details()` 先调用 ATC REST API（`POST /flight/plan/realtimePlanPage`），失败则回退到直接读取 Redis `BIZ_DATA:UAV_ROUTE` Hash，解析每个 field 的 `flightPlanList[]` 汇总所有计划。

### 10.4 复合键去重

飞行计划使用6个子计数的复合键 `"total|waiting|active|completed|rejected|cancelled"` 进行去重比较，任一子状态变化都触发推送，避免总数不变但子状态迁移时漏更新。

### 10.5 MySQL 主数据库（移除 SQLite 降级）

- **MySQL** 为测试平台唯一主数据库（`utm_simulator` 库），存配置/JSON文件/定时任务/系统日志
- pymysql 严格锁定 **1.1.0**（2.x 系列不兼容），Dockerfile 构建时验证版本
- 认证插件兼容：`mysql_native_password` 原生支持，`caching_sha2_password` 需传 `ssl={}` + `cryptography` 包
- 每次查询创建独立 cursor，修复多线程并发 `Protocol error, expecting EOF`
- MySQL 不可用时服务启动失败（不再降级到 SQLite），确保数据一致性

### 10.6 告警去重允许失败重试

`alarmStatistic` 去重仅在 REST API 调用成功时更新 `_last_alarm_count`；API 失败时保持旧值，下次同计数消息触发重试，避免"首次失败后永久跳过"的静默 bug。

### 10.7 仿真模式三合一

`SimulationManager` 统一编排 dynamic / replay / plan 三种模式，消除 `main.py` / `run_kafka.py` / `run_plan.py` 中的重复 DataSource/DataFlow 模式。

### 10.8 Kafka 消费者组 ID 带 PID

`group_id=f"utm_demo_group_{os.getpid()}"`，确保同一主机多实例同时运行时各自收到全部消息（而非在组内瓜分分区），每个仿真实例独立消费全部 trace 消息。

```bash

conda activate utm

# ── Web 控制台 ──────────────────────────
```
