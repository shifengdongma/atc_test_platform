# 低空空管自动化系统测试用例规范

> 版本: 1.0 | 更新日期: 2026-04-14 | 适用: 低空空管自动化系统

## 1. 测试用例结构标准（基于实际Excel格式）

### 1.1 标准字段定义

| 字段名 | 必填 | 说明 | 示例 |
|--------|------|------|------|
| 用例编号 | 是 | 唯一标识，建议格式：模块-功能-序号 | 告警抑制-001 |
| 业务模块 | 是 | 系统功能模块 | 告警抑制区设置 |
| 业务功能 | 否 | 子功能点 | 新增抑制区 |
| 用例名称 | 是 | 简洁描述测试目的 | 新增短期冲突告警抑制区并验证生效 |
| 前置条件 | 是 | 执行测试的必要条件 | 进入【告警管理】>【抑制区设置】 |
| 测试步骤 | 是 | 详细的操作步骤（带序号） | 1. 点击"新增"按钮... |
| 预期结果 | 是 | 每个步骤的期望输出 | 1. 多边形闭合，显示在地图上... |
| 等级 | 是 | 高/中/低 | 高 |
| 用例类型 | 否 | 功能/接口/性能/兼容性/安全 | 功能测试 |
| 测试结果 | 否 | 通过/失败/阻塞 | 通过 |
| 测试人员 | 否 | 执行人 | 张三 |
| 执行时间 | 否 | 执行日期 | 2026-04-14 |

### 1.2 优先级定义（与Excel"等级"字段对应）

| 等级 | 定义 | 执行要求 | 适用场景 |
|------|------|---------|---------|
| **高** | 核心功能，阻塞性问题 | 必须100%通过 | 主流程、关键业务规则 |
| **中** | 重要功能，主要场景 | 通过率 >= 95% | 次要功能、边界场景 |
| **低** | 一般功能，优化项 | 通过率 >= 90% | 异常场景、性能测试 |

### 1.3 业务模块分类（低空空管系统）

| 一级模块 | 二级模块 | 说明 |
|---------|---------|------|
| 告警管理 | 告警抑制区设置 | 抑制区CRUD、启用禁用 |
| | 最低安全高度预警(PMSAW) | 预警触发、确认圈数、趋势取消 |
| | 最低安全高度告警(MSAW) | 告警触发、生命周期、升级关系 |
| | 短期冲突告警(STCA) | 冲突检测、抑制逻辑 |
| 接收机管理 | 接收机基础操作 | 增删改查克隆、导入导出 |
| | 接收机注册流程 | MQTT注册、心跳上报 |
| | 接收机升级 | 固件升级、批量升级 |
| | 接收机配置下发 | 参数配置、批量下发 |
| | 接收机重启 | 远程重启、状态管理 |
| 态势监视 | 地图显示 | 航迹显示、标牌显示 |
| | 工具栏功能 | 测量、定位、鹰眼 |

| | 空域设置 | 隔离空域、适飞空域 |

## 2. 测试用例编写规范

### 2.1 用例名称规范

```
格式：{动作}-{对象}-{验证点}

✅ 好的示例：
- 新增短期冲突告警抑制区并验证生效
- 抑制区启用/禁用开关功能验证
- 验证最低安全高度预警在符合条件时正确触发
- 接收机新增-必填项缺失校验
- 正常心跳上报-30秒间隔

❌ 不好的示例：
- 测试抑制区功能
- 告警测试
- 接收机测试用例
```

### 2.2 前置条件编写规范

```
✅ 好的示例：
1. 进入【告警管理】>【抑制区设置】>【短期冲突告警/预警】
2. 地图加载正常
3. 存在测试无人机数据（使其产生短期冲突预警和告警数据）

❌ 不好的示例：
- 系统正常
- 已登录
```

### 2.3 测试步骤编写规范

```
✅ 好的示例：
1. 点击"新增"按钮
2. 在地图上连续点击绘制有效多边形（5个点），双击结束
3. 输入抑制区名称："测试抑制区-01"
4. 确认"是否启用"开关为开启状态（绿色）
5. 点击保存
6. 模拟无人机在绘制区域内产生短期冲突告警

❌ 不好的示例：
1. 打开页面
2. 操作功能
3. 检查结果
```

### 2.4 预期结果编写规范

```
✅ 好的示例：
1. 多边形闭合，显示在地图上
2. 列表新增一条记录，名称显示正确，状态为"启用"
3. 步骤6中，该区域内应不产生短期冲突告警（被成功抑制），区域外正常产生告警

❌ 不好的示例：
- 功能正常
- 显示正确
- 无错误
```

## 3. 低空空管系统专项测试要点

### 3.1 告警类测试要点

| 检查项 | 说明 | 示例 |
|--------|------|------|
| 抑制区逻辑 | 抑制区与告警的关联 | 区域内不告警、区域外正常告警 |
| 告警升级 | 预警到告警的升级 | PMSAW触发后，条件满足升级为MSAW |
| 确认圈数 | 连续确认机制 | 10次确认后告警成立 |
| 趋势取消 | 高度回升自动取消 | 开启趋势取消后，高度回升告警关闭 |
| 生命周期 | 告警自动关闭 | 超过周期时长后自动关闭 |
| 坐席隔离 | 不同坐席独立控制 | 坐席01关闭不影响坐席02 |

### 3.2 接收机管理测试要点

| 检查项 | 说明 | 示例 |
|--------|------|------|
| 设备ID规则 | 20位编码规则 | 前8位扇区+9-10位区域+11-13位类型+14-20位序号 |
| MQTT注册 | 注册流程 | 上注册、下响应、心跳维持 |
| 固件升级 | 升级流程 | 指令下发、下载、校验、升级、上报 |
| 批量操作 | 批量导入/升级/配置 | Excel导入、批量升级任务 |
| 心跳机制 | 30秒间隔、90秒离线 | 正常心跳、离线判定 |

### 3.3 态势监视测试要点

| 检查项 | 说明 | 示例 |
|--------|------|------|
| 地图显示 | 航迹、标牌、图标 | 接收机图标、覆盖区域、航迹显示 |
| 工具栏 | 测量、定位、鹰眼 | 面积测量、经纬度定位、鹰眼地图 |
| 统计指标 | 实时数据 | 无人机总数、飞行计划数、告警数 |
| 图层控制 | 显示/隐藏 | 适飞空域、隔离空域、航路航线 |

## 4. 测试用例质量检查清单

### 4.1 完整性检查

```markdown
□ 用例编号唯一且不重复
□ 业务模块分类正确
□ 用例名称清晰描述测试目的
□ 前置条件具体可准备
□ 测试步骤编号清晰（1. 2. 3.）
□ 预期结果与步骤对应
□ 等级（高/中/低）标注正确
□ 正向场景已覆盖
□ 负向场景已覆盖
□ 边界值已覆盖
```

### 4.2 可执行性检查

```markdown
□ 前置条件可实际操作准备
□ 测试步骤具体到UI元素（按钮、输入框名称）
□ 测试数据已明确（如"测试抑制区-01"）
□ 预期结果可验证（非"正常"等模糊描述）
□ 多步骤场景步骤编号连续
□ 预期结果与测试步骤数量对应
```

### 4.3 业务逻辑检查

```markdown
□ 告警类用例验证抑制逻辑
□ 接收机类用例验证ID规则
□ 升级类用例验证完整流程
□ 心跳类用例验证时间间隔
□ 地图类用例验证显示效果
□ 批量操作验证并发/性能
```

### 4.4 可追溯性检查

```markdown
□ 用例关联到需求ID（TAPD链接）
□ 用例覆盖所有需求点
□ 同一功能点多场景覆盖
□ 需求变更后用例同步更新
```

## 5. 常见问题与改进建议

### 5.1 用例名称问题

| 问题 | 改进建议 |
|------|---------|
| 名称过于简单 | 补充动作+对象+验证点 |
| 名称重复 | 增加场景区分 |
| 名称与步骤不符 | 统一描述 |

### 5.2 前置条件问题

| 问题 | 改进建议 |
|------|---------|
| 过于笼统 | 具体到菜单路径 |
| 缺少数据准备 | 补充测试数据要求 |
| 条件不可准备 | 调整为可实际操作的条件 |

### 5.3 测试步骤问题

| 问题 | 改进建议 |
|------|---------|
| 步骤过于简略 | 细化到具体UI操作 |
| 缺少数据输入 | 补充具体输入值 |
| 步骤顺序混乱 | 按操作流程重新排序 |

### 5.4 预期结果问题

| 问题 | 改进建议 |
|------|---------|
| 描述模糊 | 具体到显示内容、状态变化 |
| 与步骤不对应 | 一一对应每个步骤 |
| 缺少验证点 | 补充数据、UI、日志等多维度验证 |
