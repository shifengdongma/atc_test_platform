# 测试用例设计规范知识库

> 版本: 1.0 | 更新日期: 2026-04-14

## 1. 测试用例结构标准

### 1.1 必填字段

| 字段 | 说明 | 示例 |
|------|------|------|
| ID | 唯一标识 | TC-USER-001 |
| 标题 | 简洁描述测试目的 | 验证用户注册-正常流程 |
| 优先级 | P0/P1/P2/P3 | P0 |
| 前置条件 | 执行测试的必要条件 | 用户未登录状态 |
| 测试步骤 | 详细的操作步骤 | 1. 输入用户名... |
| 预期结果 | 每个步骤的期望输出 | 显示注册成功提示 |

### 1.2 优先级定义

| 优先级 | 定义 | 执行要求 |
|--------|------|---------|
| **P0** | 核心功能，阻塞性问题 | 必须100%通过 |
| **P1** | 重要功能，主要场景 | 通过率 >= 95% |
| **P2** | 一般功能，次要场景 | 通过率 >= 90% |
| **P3** | 边缘场景，优化项 | 根据时间执行 |

### 1.3 测试类型分类

| 类型 | 说明 | 关注点 |
|------|------|--------|
| 功能测试 | 验证业务功能正确性 | 业务规则、数据流转 |
| 接口测试 | 验证API行为 | 参数校验、响应格式 |
| 性能测试 | 验证系统性能指标 | 响应时间、吞吐量 |
| 兼容性测试 | 验证多环境兼容 | 浏览器、设备、版本 |
| 安全测试 | 验证安全防护 | 注入、越权、敏感数据 |

## 2. 测试用例设计方法

### 2.1 等价类划分 (Equivalence Partitioning)

**原则**：将输入数据划分为若干等价类，每类选一个代表测试

**分类**：
- **有效等价类**：符合规则的输入
- **无效等价类**：不符合规则的输入

**示例**：年龄输入框（1-150岁）

| 等价类 | 代表值 | 类型 |
|--------|--------|------|
| 小于最小值 | 0 | 无效 |
| 有效范围 | 25 | 有效 |
| 大于最大值 | 200 | 无效 |
| 非数字 | "abc" | 无效 |
| 空值 | "" | 无效 |

### 2.2 边界值分析 (Boundary Value Analysis)

**原则**：重点关注边界及边界附近的值

**边界点选择**：
- 最小值
- 略高于最小值
- 正常值
- 略低于最大值
- 最大值

**示例**：用户名长度（6-20字符）

| 测试点 | 值 | 说明 |
|--------|-----|------|
| 低于下限 | 5字符 | 无效 |
| 下限值 | 6字符 | 有效（边界） |
| 略高于下限 | 7字符 | 有效 |
| 正常值 | 10字符 | 有效 |
| 略低于上限 | 19字符 | 有效 |
| 上限值 | 20字符 | 有效（边界） |
| 高于上限 | 21字符 | 无效 |

### 2.3 场景法 (Scenario Testing)

**基本流**：正常业务流程（必须覆盖）
**备选流**：异常或分支流程

**示例**：用户登录流程

```
基本流：
1. 输入正确用户名
2. 输入正确密码
3. 点击登录
4. 登录成功，跳转首页

备选流：
- 用户名不存在
- 密码错误
- 账号被锁定
- 网络异常
```

### 2.4 决策表 (Decision Table)

适用于多条件组合场景

**示例**：贷款审批决策

| 条件 | 规则1 | 规则2 | 规则3 | 规则4 |
|------|-------|-------|-------|-------|
| 信用分>700 | Y | Y | N | N |
| 收入>10000 | Y | N | Y | N |
| 无逾期记录 | Y | Y | Y | N |
| **结果：通过** | ✓ | ✓ | ✗ | ✗ |

## 3. 测试用例质量门禁

### 3.1 完整性检查

```markdown
□ 每个需求至少有1个测试用例
□ 每个功能点覆盖正向场景
□ 每个功能点覆盖负向场景
□ 边界值已覆盖
□ 异常场景已考虑
```

### 3.2 可执行性检查

```markdown
□ 前置条件明确且可准备
□ 测试步骤具体可操作
□ 预期结果可验证
□ 测试数据已定义
□ 无歧义描述
```

### 3.3 可追溯性检查

```markdown
□ 用例关联到需求ID
□ 用例关联到功能点ID
□ 覆盖矩阵已更新
```

## 4. 测试用例编写规范

### 4.1 标题规范

```
格式：验证{功能}-{场景}-{预期结果}

✅ 好的示例：
- 验证用户注册-正常流程-注册成功
- 验证登录-密码错误-提示密码错误
- 验证订单创建-库存不足-提示库存不足

❌ 不好的示例：
- 测试登录功能
- 用户注册测试
- 订单测试
```

### 4.2 步骤编写规范

```
✅ 好的示例：
1. 打开登录页面 https://xxx.com/login
2. 在用户名输入框输入 "testuser"
3. 在密码输入框输入 "Test@123"
4. 点击【登录】按钮

❌ 不好的示例：
1. 打开页面
2. 输入用户名密码
3. 点击登录
```

### 4.3 预期结果规范

```
✅ 好的示例：
- 页面跳转至首页
- 页面顶部显示用户名 "testuser"
- 数据库 users 表新增一条记录

❌ 不好的示例：
- 登录成功
- 页面正常显示
- 数据正确
```

## 5. 测试数据设计

### 5.1 数据分类

| 数据类型 | 说明 | 示例 |
|----------|------|------|
| 有效数据 | 符合业务规则的数据 | 正常用户名、正确密码 |
| 无效数据 | 不符合规则的数据 | 空值、超长字符串 |
| 边界数据 | 边界及边界附近的值 | 最小长度、最大长度 |
| 随机数据 | 随机生成的测试数据 | 随机姓名、随机金额 |
| 特殊数据 | 特殊字符、注入字符串 | `<script>`, `' OR 1=1` |

### 5.2 数据准备原则

1. **独立性**：测试数据不依赖其他用例
2. **可重复**：数据可重复使用
3. **可清理**：测试后可清理
4. **代表性**：数据能代表一类场景
