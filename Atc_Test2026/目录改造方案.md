# ATC 测试平台目录改造方案（平台化版）

> 参考 TestHub 模块化架构，将测试脚本升级为**平台化测试系统**，每个模块独立且遵循统一规范。

## 一、设计原则（参考 TestHub）

| 原则 | 说明 |
|------|------|
| **模块化** | 每个测试类型为一个独立模块（类似 TestHub `apps/api_testing/`、`apps/ui_automation/`） |
| **配置中心化** | 统一 `config/` 管理环境信息，各模块通过配置中心读取，不写死连接信息 |
| **前后端分离** | `frontend/` 统一前端入口，各模块提供 `web_api.py` 供前端调用 |
| **版本追踪** | `utm_moc52_develop` 作为基线，`utm-simulator` 记录差异，支持更新对比 |
| **统一规范** | 每个模块必须包含：`README.md`、`requirements.txt`、`config.yaml`、`core/`、`web_api.py` |

## 三、各模块详细设计

### [模块1] utm_moc52_develop/ — 公司代码基线

**定位**：公司 Gitlab 拉取的最新代码，**内部完全不修改**，仅新增版本追踪目录。

**新增 `.version_info/`**：

| 文件 | 内容 |
|------|------|
| `git_config.json` | `{"url": "...", "branch": "main", "last_sync": "2026-06-22"}` |
| `sync_history.log` | 每次拉取记录：日期、commit_hash、操作人、变更文件数 |
| `db_version.json` | 数据库版本号、表结构哈希，用于判断是否需要同步数据库 |

**拉取流程**（通过 `frontend/pages/` 或命令行）：
1. 读取 `git_config.json` 配置
2. `git pull` 最新代码
3. 对比数据库版本，提示是否需要同步
4. 记录到 `sync_history.log`

---

### [模块2] utm-simulator/ — 二次开发仿真器

**定位**：从 `utm_moc52_develop` 复制后进行二次开发，与基线保持差异追踪。

**新增文件**：
- `version.md`：当前二次开发版本说明
- `sync_diff.md`：与 `utm_moc52_develop` 的差异清单（手动维护或自动对比生成）
- `sync_from_base.py`：一键从 `utm_moc52_develop` 同步最新代码并提示冲突

**同步策略**：
```bash
# 从基线同步最新代码（保留二次开发修改）
python sync_from_base.py
# 输出：冲突文件列表，需人工合并
```

### [基础设施] config/ — 配置中心

**定位**：所有环境信息的统一存储，各模块通过配置中心读取，不写死IP/端口。

```
config/
├── database/
│   └── atc_platform.db          # SQLite
│       # 表：environments (id, name, api_host, ws_host, db_host, ...)
│       # 表：sync_history (id, module, sync_time, commit_hash, ...)
├── environments/
│   ├── dev.yaml                 # 开发环境
│   ├── test.yaml                # 测试环境
│   └── prod.yaml                # 生产环境
├── settings.yaml                # 平台全局配置
└── pages/index.html             # 环境配置页面：增删改查环境
```

**SQLite 表结构**：
```sql
-- 环境表
CREATE TABLE environments (
    id INTEGER PRIMARY KEY,
    name TEXT UNIQUE,           -- 环境名称：dkkgsit、prod
    api_base_url TEXT,          -- API地址
    ws_url TEXT,                -- WebSocket地址
    db_host TEXT,               -- 数据库地址
    db_port INTEGER,
    redis_host TEXT,
    kafka_host TEXT,
    iomp_host TEXT,             -- IOMP地址
    description TEXT,
    created_at TIMESTAMP
);

-- 版本同步记录表
CREATE TABLE sync_history (
    id INTEGER PRIMARY KEY,
    module TEXT,                -- utm_moc52_develop / utm-simulator
    sync_time TIMESTAMP,
    commit_hash TEXT,
    changed_files INTEGER,
    operator TEXT
);
```

## 八、风险与注意事项

1. **`utm_moc52_develop` 不动原则**：改造期间仅新增 `.version_info/`，不修改任何原代码
2. **前端页面可选**：Phase 1 可先搭建基础框架，各模块页面后续迭代
3. **配置中心依赖**：各模块改造时必须将硬编码IP/端口改为从 `config/` 读取
4. **SQLite 并发**：如多模块同时读写配置库，需加锁或使用连接池
5. **版本同步冲突**：`utm-simulator` 与 `utm_moc52_develop` 的差异需人工维护 `sync_diff.md`
6. **备份策略**：Phase 1 前完整备份 `Atc_Test2026`
