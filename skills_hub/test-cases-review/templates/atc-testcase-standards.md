# 低空空管自动化系统测试用例规范

> 版本: 1.0 | 更新日期: 2026-04-14 | 适用: 低空空管自动化系统

## 1. 测试用例结构标准（基于实际Excel格式）

### 1.1 标准字段定义

| 字段名 | 必填 | 说明 | 示例 |
|--------|------|------|------|
| 用例编号 | 是 | 唯一标识，格式：模块拼音前缀-序号 | bjyzq-001、jsj-001 |
| 业务模块 | 是 | 系统功能模块 | 告警抑制区设置 |
| 业务功能 | 否 | 子功能点 | 新增抑制区 |
| 用例名称 | 是 | 简洁描述测试目的 | 新增短期冲突告警抑制区并验证生效 |
| 前置条件 | 是 | 执行测试的必要条件 | 进入【告警管理】>【抑制区设置】 |
| 测试步骤 | 是 | 详细的操作步骤（带序号） | 1. 点击"新增"按钮... |
| 预期结果 | 是 | 每个步骤的期望输出 | 1. 多边形闭合，显示在地图上... |
| 等级 | 是 | 高/中/低 | 高 |
| 用例类型 | 否 | 功能/接口/性能/兼容性/安全 | 功能测试 |
| 测试结果 | 否 | 通过/失败/阻塞 | 通过 |
| 测试人员 | 否 | 执行人 | 张三 |
| 执行时间 | 否 | 执行日期 | 2026-04-14 |

### 1.2 优先级定义（与Excel"等级"字段对应）

| 等级 | 定义 | 执行要求 | 适用场景 |
|------|------|---------|---------|
| **高** | 核心功能，阻塞性问题 | 必须100%通过 | 主流程、关键业务规则 |
| **中** | 重要功能，主要场景 | 通过率 >= 95% | 次要功能、边界场景 |
| **低** | 一般功能，优化项 | 通过率 >= 90% | 异常场景、性能测试 |

- 用例编号全局唯一，不可重复

## 2. 测试用例编写规范

### 2.1 用例名称规范

```
格式：{动作}-{对象}-{验证点}

✅ 好的示例：
- 新增短期冲突告警抑制区并验证生效
- 抑制区启用/禁用开关功能验证
- 验证最低安全高度预警在符合条件时正确触发
- 接收机新增-必填项缺失校验
- 正常心跳上报-30秒间隔验证

❌ 不好的示例：
- 测试抑制区功能
- 告警测试
- 接收机测试用例

**用例编号示例**：
- bjyzq-001 ~ bjyzq-014（告警抑制区设置，14条）
- zlxz-001 ~ zlxz-016（告警管理-坐席设置，16条）
- zdajy-001 ~ zdajy-016（最低安全高度预警，16条）
- zdajg-001 ~ zdajg-016（最低安全高度告警，16条）
- jsj-001 ~ jsj-050（接收机基础操作，50条）
- jsjzc-001 ~ jsjzc-010（接收机注册流程，10条）
- fxrw-001 ~ fxrw-020（飞行任务，20条）
```

### 2.2 前置条件编写规范

```
✅ 好的示例：
1. 进入【告警管理】>【抑制区设置】>【短期冲突告警/预警】
2. 地图加载正常
3. 存在测试无人机数据（使其产生短期冲突预警和告警数据）

❌ 不好的示例：
- 系统正常
- 已登录
```

### 2.3 测试步骤编写规范

```
✅ 好的示例：
1. 点击"新增"按钮
2. 在地图上连续点击绘制有效多边形（5个点），双击结束
3. 输入抑制区名称："测试抑制区-01"
4. 确认"是否启用"开关为开启状态（绿色）
5. 点击保存
6. 模拟无人机在绘制区域内产生短期冲突告警

❌ 不好的示例：
1. 打开页面
2. 操作功能
3. 检查结果
```

### 2.4 预期结果编写规范

```
✅ 好的示例：
1. 多边形闭合，显示在地图上
2. 列表新增一条记录，名称显示正确，状态为"启用"
3. 步骤6中，该区域内应不产生短期冲突告警（被成功抑制），区域外正常产生告警

❌ 不好的示例：
- 功能正常
- 显示正确
- 无错误
```

## 3. 低空空管系统专项测试要点

### 3.1 告警类测试要点

| 检查项 | 说明 | 示例 |

## 4. 测试用例质量检查清单

### 4.1 完整性检查

```markdown
□ 用例编号唯一且不重复

□ 用例名称清晰描述测试目的
□ 前置条件具体可准备
□ 测试步骤编号清晰（1. 2. 3.）
□ 预期结果与步骤对应
□ 等级（高/中/低）标注正确
□ 正向场景已覆盖
□ 负向场景已覆盖
□ 边界值已覆盖
```

### 4.2 可执行性检查

```markdown
□ 前置条件可实际操作准备
□ 测试步骤具体到UI元素（按钮、输入框名称）

□ 预期结果与测试步骤数量对应
```

## 5. 常见问题与改进建议

### 5.1 用例名称问题

| 问题 | 改进建议 |
|------|---------|
| 名称过于简单 | 补充动作+对象+验证点 |
| 名称重复 | 增加场景区分 |
| 名称与步骤不符 | 统一描述 |

### 5.2 前置条件问题

| 问题 | 改进建议 |
|------|---------|
| 过于笼统 | 具体到菜单路径 |
| 缺少数据准备 | 补充测试数据要求 |
| 条件不可准备 | 调整为可实际操作的条件 |

### 5.3 测试步骤问题

| 问题 | 改进建议 | 示例 |
|------|---------|------|
| 步骤为空 | 补充详细的操作步骤 | ❌ （空）→ ✅ 1. 点击"新增"按钮 |
| 描述模糊 | 具体到UI元素 | ❌ "操作功能" → ✅ "点击保存按钮" |
| 缺少编号 | 添加步骤编号 | ❌ 连续文本 → ✅ 1. 2. 3. |
| 过于简略 | 细化到具体操作 | ❌ "进行测试" → ✅ "输入用户名:test01" |
| 缺少数据 | 补充具体输入值 | ❌ "输入名称" → ✅ "输入名称:测试抑制区-01" |

### 5.4 预期结果问题

| 问题 | 改进建议 | 示例 |
|------|---------|------|
| 结果为空 | 补充可验证的预期结果 | ❌ （空）→ ✅ "列表显示新增记录" |
| 描述模糊 | 使用可量化标准 | ❌ "显示正确" → ✅ "列表显示3条记录" |
| 不可验证 | 具体到状态变化 | ❌ "功能正常" → ✅ "按钮变为灰色" |
| 与步骤不对应 | 一一对应每个步骤 | 步骤3条，结果也应3条 |
| 缺少验证点 | 多维度验证 | 补充数据、UI、日志验证 |

### 5.5 测试用例设计方法问题

#### 5.5.1 等价类划分问题

| 问题 | 改进建议 | 示例 |
|------|---------|------|
| 仅测试正常值 | 补充无效等价类 | 年龄：测试-1岁、200岁 |
| 缺少空值测试 | 补充空值/Null | 用户名：测试空字符串 |
| 缺少特殊字符 | 补充特殊字符 | 名称：测试@#$%等字符 |
| 缺少类型测试 | 补充类型错误 | 数字框输入字母 |

#### 5.5.2 边界值问题

| 问题 | 改进建议 | 示例 |
|------|---------|------|
| 仅测试正常范围 | 测试边界值 | 数量64个：测试63、64、65 |
| 缺少最小值 | 测试最小值及最小值-1 | 长度6字符：测试5、6、7字符 |
| 缺少最大值 | 测试最大值及最大值+1 | 长度20字符：测试19、20、21字符 |

#### 5.5.3 场景覆盖问题

| 问题 | 改进建议 | 示例 |
|------|---------|------|
| 仅正常场景 | 补充异常场景 | 网络中断、超时、并发 |
| 缺少错误处理 | 补充错误流程 | 密码错误、权限不足 |
| 缺少恢复测试 | 补充恢复流程 | 服务重启后数据恢复 |

### 5.6 完整性评审问题分级

#### 严重问题（P0 - 必须立即修复）

| 问题类型 | 判定标准 | 影响 |
|---------|---------|------|
| 测试步骤为空 | 测试步骤列无内容 | 无法执行测试 |
| 预期结果为空 | 预期结果列无内容 | 无法验证结果 |
| 用例编号重复 | 同一编号出现多次 | 无法区分用例 |

#### 一般问题（P1 - 建议尽快修复）

| 问题类型 | 判定标准 | 改进建议 |
|---------|---------|---------|
| 步骤描述模糊 | 包含"操作功能"等模糊词 | 使用具体UI元素描述 |
| 结果描述模糊 | 包含"正常"、"正确"等词 | 使用可量化标准 |
| 步骤结果不对应 | 步骤数与结果数不匹配 | 确保一一对应 |

#### 建议优化（P2 - 可选优化）

| 问题类型 | 判定标准 | 改进建议 |
|---------|---------|---------|
| 等价类覆盖不足 | 缺少无效类测试 | 补充异常输入场景 |
| 边界值覆盖不足 | 涉及数量但未测边界 | 补充最小值、最大值测试 |
| 异常场景缺失 | 仅正常流程 | 补充网络中断、数据异常 |
| 缺少步骤编号 | 步骤无1.2.3.编号 | 添加编号提高可读性 |
