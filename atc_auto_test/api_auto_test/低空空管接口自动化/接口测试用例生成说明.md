## 二、环境配置说明

### 2.1 默认环境配置（SIT）

每个 JMX 文件的 TestPlan 中包含以下用户定义变量：

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| protocol | https | 协议 |
| host | dkkgsit-test.testdolphin.com | 主机地址 |
| port | 443 | 端口 |
| jwt-token | (空) | 认证令牌，**必须手动配置** |

### 2.2 多环境支持

支持通过命令行参数覆盖环境变量：

```bash
# 切换到UAT环境
jmeter -Jhost=dkkguat-test.testdolphin.com -Jjwt-token=your_token -n -t 01_起降场管理场景_sit.jmx -l result.jtl

# 切换到本地环境
jmeter -Jhost=localhost -Jport=8080 -Jjwt-token=your_token -n -t 01_起降场管理场景_sit.jmx -l result.jtl
```

### 2.3 环境配置快速切换

在 JMeter GUI 中：
1. 打开 JMX 文件
2. 右键点击 TestPlan -> User Defined Variables
3. 修改对应变量的值

## 三、使用步骤

### 3.1 首次使用

1. **获取有效 Token**
   - 登录测试环境
   - 从浏览器开发者工具或接口响应中获取 jwt-token

2. **配置 Token**
   - 打开 JMX 文件
   - 修改 TestPlan -> User Defined Variables 中的 jwt-token 值

3. **验证执行**
   - 运行单个接口验证连通性
   - 检查响应断言结果

### 3.2 批量执行

```bash
# 执行单个场景
jmeter -n -t 接口测试用例jmx/01_起降场管理场景_sit.jmx -l results/result_01.jtl -e -o reports/report_01

# 批量执行所有场景（使用shell脚本）
for file in 接口测试用例jmx/*.jmx; do
    filename=$(basename "$file" .jmx)
    jmeter -n -t "$file" -l "results/${filename}.jtl"
done
```

### 3.3 CI/CD 集成

```yaml
# Jenkins Pipeline 示例
pipeline {
    agent any
    stages {
        stage('API Test') {
            steps {
                script {
                    def scenes = ['01_起降场管理场景', '02_扇区管理场景']
                    for (scene in scenes) {
                        sh """
                            jmeter -Jjwt-token=${JWT_TOKEN} \
                                   -n -t 接口测试用例jmx/${scene}_sit.jmx \
                                   -l results/${scene}.jtl
                        """
                    }
                }
            }
        }
    }
}
```

## 四、场景设计说明

### 4.1 场景化设计原则

为了减少 JMX 文件数量，采用**业务场景聚合**策略：

1. **按业务模块聚合**：将同一业务模块的接口组织到一个场景
2. **按优先级分层**：P0 核心场景单独成文件，P1/P2 适当合并
3. **接口依赖处理**：同一业务流程的接口按执行顺序排列

### 4.2 场景覆盖矩阵

| 业务域 | 场景文件 | 覆盖模块 | 接口数量 | 优先级 |
|--------|----------|----------|----------|--------|

| 飞行管理 | 05-06 | 飞行计划、飞行任务 | 35 | P0 |
| 设备管理 | 07, 14 | 无人机、接收机 | 17 | P1 |
| 告警监控 | 08 | 告警管理 | 13 | P1 |

## 五、测试数据说明

### 5.1 数据生成规则

测试数据采用 JMeter 内置函数动态生成：

| 数据类型 | 生成规则 | 示例 |
|----------|----------|------|
| 起降场名称 | AUTO起降场${__time(MMddHHmmss)}${__RandomString(1,ABCDEFGHJKLMN,)} | AUTO起降场0422201131A |
| 起降场编号 | ${__time(MMddHH)}${__RandomString(2,ABCDEFGHJKLMNPQRSTUVWXYZ,)} | 042220AB |
| 坐标经度 | 121.132${__RandomString(3,0123456789,)} | 121.132456 |
| 坐标纬度 | 38.726${__RandomString(3,0123456789,)} | 38.726789 |
| 无人机识别码 | UAV${__time(MMddHHmmss)}${__RandomString(4,0123456789,)} | UAV04222011310001 |

### 5.2 数据冲突避免

- 使用时间戳 + 随机字符串确保唯一性
- 测试数据前缀统一使用 "AUTO" 便于识别和清理

## 八、常见问题

### Q1: Token 过期如何处理？

A: 需要定期更新 jwt-token 变量。建议：
- 在 CI/CD 中通过脚本自动获取 Token
- 或使用长效 Token

### Q2: 如何只执行部分接口？

A: 在 JMeter 中：
1. 禁用不需要的 HTTP 请求（右键 -> Disable）
2. 或使用逻辑控制器控制执行流程

### Q3: 响应断言失败怎么办？

A: 检查：
1. Token 是否有效
2. 环境是否可访问
3. 接口路径是否正确
4. 请求参数是否符合要求

### Q4: 如何添加新的测试场景？

A: 修改 `swagger_to_jmx_generator.py` 中的 `SCENES` 配置，重新运行生成脚本。
