# 性能测试脚本生成说明

## 一、改造背景与目标

### 1.1 问题背景
原性能测试脚本存在以下问题：
- 直接修改 `env.py` 配置，影响其他测试场景
- 固定轨迹和随机仿真无人机数量受限（内置仅300个ID）
- `create_data.py` 通过 `subprocess` 启动，子进程无法继承父进程的 Monkey Patch
- 大规模并发（3000~5000架）时ID随机生成，与系统中预置航空器数据不一致

### 1.2 改造目标
- **零侵入核心代码**：不修改 `simulation_core.py`、`create_data.py`、`main.py`
- **Monkey Patch 扩展ID**：运行时扩展预置ID列表至5000个
- **直接调用 `create_data`**：避免子进程丢失扩展ID
- **多线程支持**：随机仿真可分布到多个线程/进程，提升并发能力
- **ID 全预置**：所有无人机使用系统中已导入的航空器ID，避免导入报错

## 二、核心改造点

### 2.1 Monkey Patch 扩展预置 ID 列表

所有性能测试脚本必须在 `from main import DataFlow` **之前**执行 Monkey Patch：

```python
import simulation_core as _sim_core
from uav_identifiers_extended import UAV_IDENTIFIERS_EXTENDED
_sim_core.UAV_IDENTIFIERS = UAV_IDENTIFIERS_EXTENDED
_sim_core.ACTIVE_UAV_IDENTIFIERS = UAV_IDENTIFIERS_EXTENDED
```

**关键点**：
- `uav_identifiers_extended.py` 位于 `utm_moc52_develop/` 目录
- 包含 **5000** 个预置ID（原300个 + 新增4700个）
- 扩展ID与内置ID完全无重复
- 替换后 `Simulator.generate_plan()` 和 `DroneAgent.__init__` 均使用扩展列表

### 2.2 直接调用 `create_data.main()`

**禁止**使用 `subprocess.run([sys.executable, CREATE_DATA_PY, ...])` 启动 `create_data.py`。

**正确做法**：
```python
import create_data
create_data.main(
    target_drones=FIXED_COUNT,
    origin_lat=ORIGIN_LAT,
    origin_lon=ORIGIN_LON,
    sim_radius_m=SIM_RADIUS_M,
)
```

**原因**：子进程会重新导入 `simulation_core`，无法继承父进程的 Monkey Patch，导致固定轨迹无人机也使用随机ID。

### 2.3 路径配置规范

```python
SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.dirname(SCRIPT_DIR)))
ENGINE_DIR = os.path.join(PROJECT_ROOT, "Atc_Test2026", "utm_moc52_develop")
TOOLS_DIR = os.path.join(ENGINE_DIR, "tools")

sys.path.insert(0, ENGINE_DIR)
sys.path.insert(0, TOOLS_DIR)  # 必须加入，否则 import create_data 会失败
```

### 2.4 ID 分段分配规范

所有性能测试脚本必须遵循以下ID分配规则，确保固定轨迹和随机仿真ID不冲突：

| 类型 | ID 索引范围 | 计算方式 |
|------|-----------|---------|
| 固定轨迹（create_data） | `[0, FIXED_COUNT-1]` | 从索引0开始 |
| 随机仿真线程-i | `[FIXED_COUNT + i*N, FIXED_COUNT + (i+1)*N - 1]` | `uid_start_offset = FIXED_COUNT + i * N` |

其中 `N = RANDOM_COUNT_PER_THREAD`（每线程随机仿真架数）。

**总ID使用量必须 ≤ 5000**。

## 四、新增性能测试脚本开发指南

### 4.1 模板结构

新建性能测试脚本必须包含以下结构：

```python
# -*- coding: utf-8 -*-
"""
性能测试脚本：XXX场景测试（改造版）

测试场景：
  - FIXED_COUNT 架：create_data.py 生成固定轨迹数据，由 run_kafka.py 按秒发送
  - RANDOM_COUNT 架：main.py 实时仿真随机生成并发送遥测
  - WebSocket 统计：客户端ws无人机数量统计.py 实时统计接收数量
"""
import os
import sys
import subprocess
import time
import signal
import threading

# ── 路径配置 ─────────────────────────────────────────────────────────
SCRIPT_DIR = os.path.dirname(os.path.abspath(__file__))
PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.dirname(SCRIPT_DIR)))
ENGINE_DIR = os.path.join(PROJECT_ROOT, "Atc_Test2026", "utm_moc52_develop")
TOOLS_DIR = os.path.join(ENGINE_DIR, "tools")

sys.path.insert(0, ENGINE_DIR)
sys.path.insert(0, TOOLS_DIR)

# ========== Monkey Patch：扩展内置 ID 列表至 5000 个 ==========
import simulation_core as _sim_core
from uav_identifiers_extended import UAV_IDENTIFIERS_EXTENDED
_sim_core.UAV_IDENTIFIERS = UAV_IDENTIFIERS_EXTENDED
_sim_core.ACTIVE_UAV_IDENTIFIERS = UAV_IDENTIFIERS_EXTENDED
# =============================================================

CREATE_DATA_PY = os.path.join(TOOLS_DIR, "create_data.py")
RUN_KAFKA_PY = os.path.join(TOOLS_DIR, "run_kafka.py")
WS_STATS_PY = os.path.join(SCRIPT_DIR, "客户端ws无人机数量统计.py")

# ── 常量（场景参数，全部在本脚本中配置）───────────────────────────────
FIXED_COUNT = 0              # 固定轨迹无人机数量
RANDOM_COUNT = 3000          # 随机仿真无人机数量（单线程时）
# RANDOM_THREAD_COUNT = 3    # 多线程时使用
# RANDOM_COUNT_PER_THREAD = 1000
ENABLE_WS_STATS = False      # WebSocket统计开关

ORIGIN_LAT = 40.818724       # 仿真中心纬度
ORIGIN_LON = 85.070136       # 仿真中心经度
SIM_RADIUS_M = 100000.0      # 仿真有效半径
```

### 4.2 单线程 DataFlow 模式

适用于 `RANDOM_COUNT ≤ 3000` 的场景：

```python
def step2_run_concurrent():
    from main import DataFlow
    dataflow = DataFlow(
        target_drones=RANDOM_COUNT,
        origin_lat=ORIGIN_LAT,
        origin_lon=ORIGIN_LON,
        sim_radius_m=SIM_RADIUS_M,
        uid_start_offset=FIXED_COUNT,
    )
```

### 4.3 多线程 DataFlow 模式

适用于 `RANDOM_COUNT > 3000` 或需要分散负载的场景：

```python
def run_dataflow_thread(thread_id, target_drones, uid_start_offset,
                        dataflow_list, stop_event):
    from main import DataFlow
    dataflow = DataFlow(
        target_drones=target_drones,
        origin_lat=ORIGIN_LAT,
        origin_lon=ORIGIN_LON,
        sim_radius_m=SIM_RADIUS_M,
        uid_start_offset=uid_start_offset,
    )
    dataflow_list.append(dataflow)
    while not stop_event.is_set():
        time.sleep(0.5)
    dataflow.stop()

# 主线程启动多个线程
for i in range(RANDOM_THREAD_COUNT):
    offset = FIXED_COUNT + i * RANDOM_COUNT_PER_THREAD
    t = threading.Thread(target=run_dataflow_thread, args=(...))
    t.start()
```

### 4.4 ID 分配检查清单

新建脚本前必须确认：

- [ ] 固定轨迹数量 `FIXED_COUNT` 已确定
- [ ] 随机仿真数量 `RANDOM_COUNT` 或 `RANDOM_THREAD_COUNT * RANDOM_COUNT_PER_THREAD` 已确定
- [ ] 总ID使用量 `= FIXED_COUNT + 总随机数` ≤ 5000
- [ ] 每个线程/进程的 `uid_start_offset` 计算正确：`FIXED_COUNT + i * N`
- [ ] 随机仿真ID区间不与固定轨迹重叠
- [ ] 各线程/进程间ID区间不重叠

### 4.5 坐标与半径配置建议

| 测试场景 | 坐标建议 | 半径建议 | 说明 |
|---------|---------|---------|------|
| 大规模并发（3000+） | 新疆扇区 (40.8, 85.0) | 100000m | 大范围分散，降低密度 |
| 混合告警/冲突检测 | 新疆扇区 (40.8, 85.0) | 5000~20000m | 中等范围，增加相遇概率 |
| 禁飞区告警 | 西藏禁飞区 (32.5, 85.5) | 10000m | 特定区域测试 |
| 城市低空 | 根据实际城市调整 | 5000m | 高密度场景 |

## 六、常见问题

### Q1: 子进程无法继承 Monkey Patch？
**A**: 必须使用 `import create_data; create_data.main(...)` 直接调用，禁止使用 `subprocess.run`。

### Q2: ID 冲突怎么办？
**A**: 检查 `uid_start_offset` 设置。固定轨迹使用 `[0, FIXED_COUNT-1]`，随机仿真必须从 `uid_start_offset=FIXED_COUNT` 开始。

### Q3: 多线程 DataFlow 如何协调停止？
**A**: 使用 `threading.Event`，主线程调用 `event.set()` 通知所有子线程停止，子线程轮询 `event.is_set()`。

### Q4: 5000个ID不够怎么办？
**A**: 修改 `uav_identifiers_extended.py` 增加更多批次，或调整 `_generate_batch` 参数扩展至更大数量。注意 `DroneAgent.__init__` 中的线性查找性能。

### Q5: run_kafka.py 读取不到数据？
**A**: 确保 `create_data.main()` 执行成功，且 `mock/` 目录已生成 `redis_route.json` 和 `kafka_data.json`。
