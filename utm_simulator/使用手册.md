# utm_moc52 部署与使用手册

本文说明如何在海豚运维（Dolphin）环境中部署 UTM 仿真数据注入服务（`utm_v3`），以及如何在本机维护环境配置、调整仿真区域与无人机数量。

---

## 源码目录结构说明

项目根目录 **`utm_moc52/`** 主要布局如下：

```text
utm_moc52/
├── main.py                 # 主入口：DataSource、仿真循环、Redis/Kafka 读写
├── simulation_core.py      # 无人机仿真核心（动力学、禁飞区、ORIGIN_LAT/LON 等）
├── kafka_proc.py           # Kafka 生产者/消费者封装
├── redis_client.py         # Redis 客户端封装
├── env.py                  # 运行时连接配置（部署前按 env.md 填写目标环境）
├── env.md                  # 多环境说明与示例配置（文档，非 Python 导入）
├── requirements.txt        # Python 依赖列表
├── deploy_repeat.sh        # 海豚部署：run_kafka_alive + lines_to_redis_route（支持 --count）
├── deploy.sh               # 备选部署：main.py 流程
├── packages/               # 离线 wheel（pip download 生成，打包 zip 时须包含）
├── pylib/                  # 与 UTM 核心一致的数据结构与引擎封装
│   ├── structs.py
│   └── engine.py
├── tools/                  # 工具与数据注入脚本
│   ├── run_kafka_alive.py  # 长期运行注入（deploy_repeat.sh 默认启动）
│   ├── run_kafka.py        # Mock 数据注入参考实现
│   ├── lines_to_redis_route.py  # 航线写入 Redis（--count 控制基础航线数量）
│   ├── nfzs.py             # 禁飞区/空域上传
│   ├── transform.py、create_data.py、trajectory_accuracy*.py、kafka_read_latest.py 等
│   └── ...
├── _source/                # 算法对接规范与示例数据（JSON、对接文档等）
├── mock/、json/            # 运行时或本地验证生成的 JSON/HTML 等输出
├── lines.json              # 航线数据源（部分工具使用）
├── 使用手册.md             # 本文档
└── *.html                  # 本地演示页面（可选）
```

**简要对照**

| 路径                             | 作用                                                                  |
| -------------------------------- | --------------------------------------------------------------------- |
| `main.py`                        | 单机/主仿真入口                                                       |
| `simulation_core.py`             | 仿真区域中心、无人机行为与禁飞区逻辑                                  |
| `tools/run_kafka_alive.py`       | 服务端 **`deploy_repeat.sh`** 后台进程                                |
| `tools/lines_to_redis_route.py`  | 将航线写入 Redis，无人机数量由 `--count` 传入                         |
| `env.py` / `env.md`              | 运行配置 / 多环境维护说明                                             |
| `packages/` + `requirements.txt` | 离线安装依赖，部署脚本 `pip install --no-index --find-links=packages` |

## 一、环境与配置说明

### 1.1 `env.py` 与 `env.md` 的关系

- 运行时代码从 **`env.py`** 读取 Redis、Kafka 连接信息（`redis_ip`、`redis_port`、`redis_password`、`kafka_url`）。
- **`env.md`** 用于集中维护**多套环境**的说明：各环境的 Dolphin 入口、账号提示、以及对应的 `redis_*` / `kafka_url` 示例值。
- **部署到某环境前**：打开 `env.md`，找到目标环境（如「24」「25」「atc」「实验局」等）对应的配置块，将其中变量**抄写到** `env.py` 中，保存后再打包上传。不要把敏感信息提交到公共仓库；生产密钥以运维规范为准。

### 1.2 `env.md` 中的典型结构

每个环境块一般包含：

- Dolphin 项目链接（可选）
- `redis_ip` / `redis_port` / `redis_password`
- `kafka_url`（多 broker 时用英文逗号分隔）

内网 K8s 等环境可能使用服务名（如 `redis-atc`、`dol-kafka-0....:9092`），以实际集群为准。

## 二、打包 `utm_moc52.zip`

### 2.1 准备离线依赖目录 `packages`（推荐）

服务端首次部署会执行：

```bash
pip3 install --no-index --find-links=packages -r requirements.txt
```

因此压缩包内**应包含** `packages` 目录（离线 wheel/源码包）。若本地尚无该目录，可在项目根目录执行（需联网）：

```bash
pip download -r requirements.txt -d ./packages
```

### 2.2 压缩范围说明

生成 **`utm_moc52.zip`** 时，请将 **`packages` 目录以及项目部署所需的其余文件**一并打入压缩包（即包含 `packages/`、`requirements.txt`、`tools/`、`main.py`、`simulation_core.py`、`redis_client.py`、`kafka_proc.py`、`pylib/`、`_source/`、`deploy_repeat.sh` 等完整可运行目录树）。  
**不要**只打部分文件，否则解压到 `/opt/kdm/utm_moc` 后脚本无法找到依赖或工具。

### 2.3 在 Windows 上生成 zip 的示例

在项目根目录（`utm_moc52`）下， 将**整个项目内容**打包为 `utm_moc52.zip`，或仅将「含 `packages` 的完整目录及之后的所有文件」压缩为一个 zip，根目录解压后应能直接看到 `packages`、`requirements.txt`、`tools` 等。

> **注意**：压缩包根目录结构应与仓库一致：解压后 `cd /opt/kdm/utm_moc` 能看到 `packages`、`tools`、`deploy_repeat.sh` 等。

## 三、海豚运维（Dolphin）操作步骤

### 3.1 打开 `utm_v3` 服务并上传压缩包

1. 登录海豚运维，进入 **UTM** 相关项目部署页（具体 URL 以 `env.md` 中对应环境链接或运维提供为准）。
2. 找到 **`utm_v3`** 服务（名称以实际部署为准）。
3. 使用平台提供的**文件上传**功能，将本机生成的 **`utm_moc52.zip`** 上传到服务器（脚本默认从 **`/tmp/utm_moc52.zip`** 读取，若平台上传到其它路径，需先 `cp` 到 `/tmp/utm_moc52.zip`）。

### 3.2 在服务终端执行部署命令

在 **`utm_v3` 服务对应的 Web 终端**（或 SSH 到同一容器/主机）中执行：

```bash
cd /tmp && unzip -o utm_moc52.zip && bash deploy_repeat.sh
```

- `unzip -o`：解压并覆盖已有文件。
- `deploy_repeat.sh`：将包同步到 `/opt/kdm/utm_moc`，按需 `pip install`，写入航线并后台启动 `tools/run_kafka_alive.py`，日志写入 **`/opt/kdm/utm_moc/output.log`**。

### 3.3 指定无人机数量（可选）

默认仿真目标无人机数量为 **60**。若需修改，传入 `--count`：

```bash
cd /tmp && unzip -o utm_moc52.zip && bash deploy_repeat.sh --count 120
```

`--count` 会透传给 `tools/lines_to_redis_route.py` 的同名 `--count` 参数。

## 四、验证模拟是否正常运行

在**新开一个终端**（与部署终端分离，避免阻塞），执行：

```bash
tail -f /opt/kdm/utm_moc/output.log
# 或执行 bash /tmp/deploy_repeat.sh -o
```

正常时应能看到 Python 脚本持续输出（无立即退出、无反复 Traceback）。按 `Ctrl+C` 可停止跟踪日志，**不会**停止后台仿真进程。

若日志无输出或进程退出，请检查：

- `env.py` 中 Redis/Kafka 是否与当前环境一致；
- `packages` 是否完整、`pip install` 是否成功；
- 网络与 Topic 权限是否正常。

## 五、调整仿真区域中心点

仿真地理中心由 **`simulation_core.py`** 中的常量控制：

| 常量         | 含义             | 默认值（示例）       |
| ------------ | ---------------- | -------------------- |
| `ORIGIN_LAT` | 仿真区域中心纬度 | `40.01960735975581`  |
| `ORIGIN_LON` | 仿真区域中心经度 | `116.56410476837016` |

修改后需重新打包 **`utm_moc52.zip`** 并按第三节重新部署，远端才会生效。

说明：注释中写的是「苏州金鸡湖附近」等演示区域，实际数值以文件中当前常量为准；经纬度使用 WGS84 意义下的度。

## 七、与 `deploy.sh` 的区别（供对照）

| 脚本               | 典型用途                                                              |
| ------------------ | --------------------------------------------------------------------- |
| `deploy_repeat.sh` | 使用 `run_kafka_alive.py` + `lines_to_redis_route.py`，支持 `--count` |
| `deploy.sh`        | 使用 `main.py` 的部署流程                                             |

本手册步骤针对 **`deploy_repeat.sh`** 与 **`utm_moc52.zip`** 流程编写；若改用 `deploy.sh`，请以该脚本内逻辑为准。
