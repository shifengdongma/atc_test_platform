# Docker 部署与 MySQL 排查命令手册

## 一、首次部署

```bash
cd /opt/atc_test_platfrom
docker compose -f docker/docker-compose.yml build --no-cache
docker compose -f docker/docker-compose.yml up -d
```

## 二、启动后立即检查（确认 MySQL 连接状态）

```bash
docker logs utm-simulator 2>&1 | grep -E "MySQL|mysql_db|MysqlDbClient|pymysql"

```

## 三、MySQL 连接故障排查（按顺序执行）

### Step 1 — 验证 pymysql 是否安装

```bash
docker exec utm-simulator python3 -c "import pymysql; print(pymysql.__version__)"
```

- 正常输出：`1.1.0`（或 1.x 版本号）
- 若无输出或报 `ModuleNotFoundError`：镜像构建时 pip install 失败，需重建

### Step 2 — 验证 MySQL 客户端模块能否导入

```bash
docker exec utm-simulator python3 -c "
import sys
sys.path.insert(0, '/app/atc_api_autotest/api_tools')
from mysqldbclient import MysqlDbClient
print('MysqlDbClient 导入成功')
"
```

### Step 3 — 检查容器读取到的 MySQL 配置

```bash
docker exec utm-simulator python3 -c "
import sys; sys.path.insert(0, '/app/common')
from config import load_mysql_config
cfg = load_mysql_config()
print(f'configured={cfg.configured}')
print(f'host={cfg.host}')
print(f'port={cfg.port}')
print(f'user={cfg.user}')
print(f'database={cfg.database}')
print(f'password={\"***\" if cfg.password else \"(空)\"}')
"
```

关键检查：
- `configured=True` — MySQL 已配置
- `host` — 不能是 `127.0.0.1` 或 `localhost`
- `user` / `password` — 确认与 MySQL 服务器一致

### Step 4 — 从容器测试 MySQL 网络连通性

```bash
docker exec utm-simulator timeout 5 bash -c "echo >/dev/tcp/10.165.32.147/3306 && echo 'TCP 可达' || echo 'TCP 不可达'"
```

如不可达，检查：
- docker-compose.yml 中容器是否在正确的 Docker 网络中
- MySQL 服务器防火墙是否允许容器 IP 访问

### Step 5 — 从容器内用 pymysql 直连测试

```bash
docker exec utm-simulator python3 -c "
import pymysql
conn = pymysql.connect(
    host='10.165.32.147', port=3306,
    user='utm', password='<实际密码>',
    database='utm_simulator',
    ssl={}, connect_timeout=10
)
print('MySQL 连接成功')
conn.close()
"
```

### Step 6 — 查看容器 IP（排查 Access denied）

```bash
docker exec utm-simulator hostname -I
```

MySQL `Access denied` 错误中的 IP（如 `'utm'@'172.18.0.1'`）就是这个容器的 IP。
需在 MySQL 服务器上确认该 IP 已授权。

## 四、常见 MySQL 错误与解决

### 错误 1：`Access denied for user 'utm'@'172.18.0.x'`

**原因**：MySQL 用户 `utm` 未授权容器 IP。

**解决**：在 MySQL 服务器执行：
```sql
CREATE USER IF NOT EXISTS 'utm'@'%' IDENTIFIED BY '<实际密码>';
GRANT ALL PRIVILEGES ON utm_simulator.* TO 'utm'@'%';
FLUSH PRIVILEGES;
SELECT host, user FROM mysql.user WHERE user='utm';
```

> `'%'` 表示允许任意 IP。如需限制可改为具体 IP 段如 `'172.18.0.%'`。

### 错误 2：`Protocol error, expecting EOF`

**原因**：pymysql 连接在多线程并发查询时数据包交错（已通过 `threading.RLock` 修复）。

**验证**：重启容器后查看日志是否还有此错误。

### 错误 3：`Can't connect to MySQL server on '10.165.32.147'`

**原因**：容器网络不通。

**排查**：
```bash
docker exec utm-simulator ping -c 3 10.165.32.147
docker network inspect atc_test_platfrom_utm-net
```

### 错误 4：`MySQL 未配置 (UTM_MYSQL_HOST 未设置)`

**原因**：docker-compose.yml 中未设置环境变量。

**解决**：在 1Panel 或 docker-compose.yml 的 `environment` 中添加：
```yaml
- UTM_MYSQL_HOST=10.165.32.147
- UTM_MYSQL_PORT=3306
- UTM_MYSQL_USER=utm
- UTM_MYSQL_PASSWORD=<实际密码>
- UTM_MYSQL_DB=utm_simulator
```

## 五、更新部署（代码变更后）

```bash
cd /opt/atc_test_platfrom
docker compose -f docker/docker-compose.yml down
docker volume rm atc_test_platfrom_utm-database    # ⚠ 命名卷缓存旧代码，必须删除
docker builder prune -af
docker compose -f docker/docker-compose.yml build --no-cache
docker compose -f docker/docker-compose.yml up -d
docker logs -f utm-simulator
```

## 六、进入容器手动操作

```bash
docker exec -it utm-simulator bash
```

进入后可执行：
```bash
# 查看代码版本
cat /app/database/mysql_db_manager.py | head -5

# 测试 MySQL CRUD
python3 -c "
import sys; sys.path.insert(0, '/app/database'); sys.path.insert(0, '/app')
import mysql_db_manager
mysql_db_manager.init_tables()
rows = mysql_db_manager.query_all('sim_json_files')
print(f'sim_json_files 表记录数: {len(rows)}')
"

# 查看 pip 包
pip list | grep -i pymysql

# 查看环境变量
env | grep UTM_MYSQL
```

## 七、达梦数据库问题排查

达梦是只读的外部 ATC 数据库，故障不影响 MySQL 功能。

```bash
docker logs utm-simulator 2>&1 | grep -E "达梦|DmDb|dmPython|dmdbclient|air_route"
```

正常输出：
```
[DmDbClient] 成功连接到达梦数据库 10.165.32.32:5237, 模式: ATC_DKWRJ_TEST
[DmDbClient] 查询表: ATC_DKWRJ_TEST.air_route
[DmDbClient] 返回 90 条记录
```

> 达梦密码在 `atc_api_autotest/env.py` 的 `DB_PASSWORD`，不在环境变量中。
