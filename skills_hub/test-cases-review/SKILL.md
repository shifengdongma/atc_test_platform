# 测试用例评审助手

基于本地知识库执行标准化的测试用例评审流程，支持测试用例质量检查、规范性验证、完整性评估。

## 知识库结构

本技能使用以下知识库文件（位于 `templates/` 目录）：

| 知识库文件 | 用途 | 调用方式 |
|-----------|------|---------|
| `testcase-standards.md` | 测试用例设计规范 | @templates/testcase-standards.md |
| `atc-testcase-standards.md` | 低空空管系统测试用例规范 | @templates/atc-testcase-standards.md |
| `testcase-template.xlsx` | Excel测试用例格式模板 | @templates/testcase-template.xlsx |
| `testcase-templates.yaml` | 测试用例结构模板 | @templates/testcase-templates.yaml |
| `boundary-analysis.md` | 边界值分析方法 | @templates/boundary-analysis.md |
| `equivalence-partition.md` | 等价类划分方法 | @templates/equivalence-partition.md |
| `scenario-design.md` | 场景设计方法 | @templates/scenario-design.md |
| `api-test-patterns.md` | 接口测试模式 | @templates/api-test-patterns.md |

## 使用方法

### 方式1：评审Excel测试用例文件

```
请根据以下知识库，对上传的Excel测试用例进行评审：
- 通用规范：@templates/testcase-standards.md
- 低空空管规范：@templates/atc-testcase-standards.md
- 接口测试规范：@templates/api-test-patterns.md

评审要求：
1. 检查用例编号规范性（是否使用拼音前缀，如bjyzq-001、jsj-001）
2. 检查用例结构完整性（编号、标题、前置条件、步骤、预期结果、等级）
3. 检查用例可执行性（步骤是否具体、预期结果是否可验证）
4. 检查覆盖度（正向、负向、边界场景）
5. 检查可追溯性（是否关联需求）
6. 输出评审报告，包含问题清单和改进建议
```

### 方式2：评审特定模块测试用例

```
请根据 @templates/atc-testcase-standards.md 中的规范，对以下模块的测试用例进行专项评审：

模块：告警抑制区设置
编号前缀：bjyzq
用例数量：14条（bjyzq-001 ~ bjzq-014）

评审重点：
1. 用例编号是否符合拼音前缀规范（bjyzq-001）
2. 抑制区逻辑验证是否完整
3. 边界值是否覆盖（64个上限、3个点最小）
4. 异常场景是否考虑（自相交多边形、名称重复）
```

### 方式3：生成测试用例评审报告

```
请对以下测试用例文件生成完整的评审报告：
- 文件路径：[Excel文件路径]
- 评审标准：@templates/atc-testcase-standards.md

输出要求：
1. 用例概览（总数、模块分布、等级分布）
2. 问题统计（严重/一般/建议）
3. 详细问题清单（位置、描述、影响、建议）
4. 优秀用例示例
5. 整体评价和改进建议
```

### 方式4：基于模板创建新测试用例

```
请根据 @templates/testcase-template.xlsx 中的格式模板，为以下需求创建测试用例：

需求描述：
[粘贴需求]

模块：[业务模块]
功能：[业务功能]

要求：
1. 使用标准Excel格式（用例编号、业务模块、业务功能、用例名称、前置条件、测试步骤、预期结果、等级）
2. 覆盖正向、负向、边界场景
3. 用例名称遵循"动作-对象-验证点"格式
4. 等级标注合理（高/中/低）
```

### 方式5：测试用例完整性分析

```
请对以下测试用例进行完整性分析，重点检查测试步骤和预期结果：
- 文件路径：[Excel文件路径]
- 分析标准：@templates/atc-testcase-standards.md

分析要求：
1. 检查测试步骤完整性（是否为空、是否模糊、是否有编号）
2. 检查预期结果完整性（是否为空、是否可验证、是否与步骤对应）
3. 检查测试用例设计方法覆盖（等价类、边界值、场景法）
4. 识别遗漏或需要补充的测试场景
5. 输出完整性分析报告

输出格式：
1. 问题统计（按严重程度、按问题类别）
2. 测试设计方法覆盖分析
3. 优先改进建议（P0/P1/P2）
4. 详细问题清单
```

### 方式6：生成带标记的Excel分析报告

```
请对以下测试用例文件生成带标记的Excel分析报告：
- 文件路径：[Excel文件路径]

要求：
1. 在原Excel中标记问题单元格：
   - 红色：严重问题（步骤/结果为空）
   - 橙色：一般问题（描述模糊）
   - 黄色：建议优化
2. 添加批注说明具体问题
3. 生成汇总报告Excel（问题统计、设计方法参考）
4. 生成详细分析报告（Markdown格式）
```

## 评审检查清单

### 结构完整性
- [ ] 用例编号使用拼音前缀（如bjyzq-001、jsj-001）
- [ ] 用例编号唯一且不重复
- [ ] 同一模块内编号连续（001、002、003）
- [ ] 业务模块分类正确
- [ ] 用例名称清晰描述测试目的
- [ ] 前置条件具体可准备
- [ ] 测试步骤编号清晰
- [ ] 预期结果与步骤对应
- [ ] 等级（高/中/低）标注正确

### 可执行性
- [ ] 前置条件可实际操作准备
- [ ] 测试步骤具体到UI元素
- [ ] 测试数据已明确
- [ ] 预期结果可验证（非模糊描述）
- [ ] 多步骤场景步骤编号连续

### 测试步骤完整性（专项检查）
- [ ] 测试步骤不为空
- [ ] 测试步骤无模糊描述（如"操作功能"、"进行检查"）
- [ ] 测试步骤有编号（1. 2. 3.）
- [ ] 测试步骤具体到UI元素（按钮、输入框名称）
- [ ] 测试步骤包含具体输入值

### 预期结果完整性（专项检查）
- [ ] 预期结果不为空
- [ ] 预期结果无模糊描述（如"正常"、"正确"、"成功"）
- [ ] 预期结果可验证（具体到显示内容、状态变化）
- [ ] 预期结果与测试步骤数量对应
- [ ] 预期结果包含多维度验证（数据、UI、日志）

### 测试用例设计方法覆盖
- [ ] 等价类划分：有效等价类已覆盖
- [ ] 等价类划分：无效等价类已覆盖
- [ ] 等价类划分：空值/Null值已测试
- [ ] 边界值分析：最小值、最大值、边界附近已测试
- [ ] 场景法：基本流（正常流程）已覆盖
- [ ] 场景法：备选流（异常流程）已覆盖
- [ ] 错误推测：常见错误已考虑

### 覆盖度
- [ ] 正向场景已覆盖
- [ ] 负向场景已覆盖
- [ ] 边界值已覆盖
- [ ] 异常场景已考虑

### 可追溯性
- [ ] 用例关联到需求ID
- [ ] 用例覆盖所有需求点
- [ ] 同一功能点多场景覆盖

## 知识库扩展

如需添加自定义评审标准：
1. 在 `templates/` 目录创建新的 `.md` 文件
2. 定义评审规则和检查清单
3. 在评审时引用
