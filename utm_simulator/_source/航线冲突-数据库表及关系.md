# 航线冲突检测 - 数据库表及关系

> 依据 `算法对接2026030301.md` 中「航线冲突检测」章节「待检测航线相关数据库表结构」整理。

## 一、业务说明

飞行任务/飞行计划提交与审批阶段，系统基于**已提交且已批准的飞行计划**，在四维（空间+时间）空域内进行冲突仿真与检测。待检测数据需同时满足：

1. **飞行计划状态**：审批通过后直至执行结束前的所有状态  
   `APPROVED`（审批通过）、`PREA`（预激活）、`CONTROL`（管制状态）、`UNCONTROL`（非管制状态）、`SUSP`（悬挂）。
2. **飞行任务空域类型**：非隔离空域（`NON_SEGREGATED`）。
3. **逻辑删除**：上述所有表中 `IS_DELETED = 0`。

## 二、表清单

| 序号 | 表名 | 中文名 | 说明 |
| --- | --- | --- | --- |
| 1 | `flight_task` | 飞行任务表 | 任务主表，含空域类型、任务状态等 |
| 2 | `flight_task_period` | 飞行任务时段表 | 任务的时间段（开始/结束时间） |
| 3 | `flight_task_line` | 飞行任务航线表 | 任务下的一条航线（离场/起飞/进场/降落点等） |
| 4 | `flight_task_line_segment` | 飞行任务航线段表 | 航线的航段或作业区（2-航段，3-作业区） |
| 5 | `flight_plan` | 飞行计划表 | 计划主表，关联任务，含计划状态、起飞/降落时间等 |
| 6 | `flight_plan_uav_info` | 飞行计划-航空器表 | 计划与无人机的多对多关系，含识别码等 |
| 7 | `uav_info` | 航空器信息表 | 无人机基础信息（型号、识别码、性能等） |

## 五、参考查询（待检测航线）

文档中给出的多表关联查询示例（满足上述业务条件）：

```sql
SELECT * FROM flight_plan fp
LEFT JOIN flight_task ft ON fp.task_id = ft.id
LEFT JOIN flight_task_period ftp ON ftp.task_id = ft.id
LEFT JOIN flight_task_line ftl ON ftl.task_id = ft.id
LEFT JOIN flight_task_line_segment ftls ON ftl.id = ftls.task_line_id
LEFT JOIN flight_plan_uav_info fpui ON fpui.plan_id = fp.id
WHERE fp.is_deleted = 0
  AND ft.is_deleted = 0
  AND ftp.is_deleted = 0
  AND ftl.is_deleted = 0
  AND ftls.is_deleted = 0
  AND fpui.is_deleted = 0
  AND fp.flight_plan_status IN ('APPROVED','PREA','CONTROL','UNCONTROL','SUSP')
  AND ft.airspace_type = 'NON_SEGREGATED';
```

## 六、各表简要说明

- **flight_task**：任务编号、名称、状态、空域类型（`SEGREGATED`/`NON_SEGREGATED`）、无人机类型等。
- **flight_task_period**：任务的开始时间、结束时间，用于冲突检测的时间窗口。
- **flight_task_line**：一条航线的整体信息（离场点、起飞点、进场点、降落点经纬高）。
- **flight_task_line_segment**：航线的每一段（type=2 航段，含起终点、宽度、保护区高度；type=3 作业区，含底高、顶高、区域 polygon）。
- **flight_plan**：计划编号、关联任务、计划状态、预计起飞/降落时间等；冲突检测按「计划」维度进行。
- **flight_plan_uav_info**：某计划使用的无人机列表（含 `UAV_IDENTIFY_CODE` 等），用于与算法请求中的 `uavIdentifyCodes` 对应。
- **uav_info**：无人机主数据，冲突检测如需机型、类型（如 LIGHT/SMALL/MEDIUM/LARGE）等可从本表或通过 `flight_plan_uav_info` 关联获取。
