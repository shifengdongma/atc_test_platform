**核心成果**：
1. ✅ **修复 Dynamic 模式 C-level 崩溃**（核心问题）：kafka-python 的 KafkaProducer/KafkaConsumer 后台 I/O 线程与 Simulator 的 ctypes 结构体内存操作在 Windows 下并发触发段错误，Python 异常机制无法捕获。解决方案：将 Kafka 客户端初始化推迟到首次实际使用时（惰性初始化），创建失败时自动降级为无 Kafka 模式
2. ✅ **新增容错降级机制**：Kafka 不可用时仿真继续运行不崩溃（遥测不发送、trace 不消费），记录日志提示
3. ✅ **修复 async_mode**：threading 模式替代 eventlet，避免 monkey_patch 破坏 C++ Simulator

**诊断过程**：
1. 在 `_tick_dynamic()` 各步骤插入诊断打印，确定崩溃点为 `send_bulk()` 调用
2. 逐个禁用 `_consume_trace`（Kafka 消费者）→ 崩溃点前移，确认消费者也是崩溃源

4. 对比 Plan 模式（同样使用 Kafka 但无 Simulator ctypes 操作）→ 确认是 Simulator + Kafka 并发导致
